## The project

Static marketing site for Suder, LLC (Cincinnati land use / zoning / commercial
real estate firm). Generated by a Python script, not a framework.

- **Repo:** `azm1000/suder-website`
- **Branches:** `main` is production. Feature work goes on
  `claude/compassionate-darwin-xdkgqp`, then fast-forwards into `main`.
  Both currently at `2cfcc9c`.
- **Deploy:** Netlify, from `main`, publishing `public/`. A push to `main`
  deploys immediately — there is no staging.

## Rules that are not negotiable

`CLAUDE.md` in the repo root is binding. Read it first. In short:

1. Never hand-edit `public/**/*.html`. Edit `src/site_content.py` or
   `src/landing_content.py`, then run `python3 src/build.py`. Commit `src/` and
   `public/` together.
2. CSS and JS live in `public/assets/`. After changing either, bump `V` in
   `src/build.py` — assets are served immutable for a year, so a stale `V`
   means nobody sees the change.
3. New images get new filenames. Never overwrite an image in place.
   Headshots are 4:5 `*-portrait.jpg` (900x1125) and 3:2 `*-wide.jpg`.
4. Do not name confidential clients. Only verified matters go on Results.
   Award years must match Sean's current listings.
5. Commit as `Josh Bernstein <josh@virtutelegal.com>` with the Co-Authored-By
   trailer.

## Layout

| Path | What it holds |
|---|---|
| `src/build.py` | The generator. `V`, page templates, `hero()`, `spinner()`, `stats_band()`, one `build_*()` per section |
| `src/site_content.py` | Firm details, practices, reel words, hero slides, results, opinions, jurisdictions, awards, team, photo credits |
| `src/landing_content.py` | Long-form copy for the seven practice pages. Its `results` lists are planning notes and are **not** rendered |
| `public/` | Generated output. Only this directory is published |
| `public/assets/css/site.css`, `js/site.js` | Hand-maintained, not generated |
| `src/signature/` | Email-signature generators and built Outlook packages for the four attorneys |

## Working on it

```bash
python3 src/build.py                 # regenerate public/
cd public && python3 -m http.server 8899   # preview at localhost:8899
```

Chromium for Playwright is at `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`
— pass it as `executable_path`; `playwright install` will not work.

**Outbound network is locked to package registries.** github.com works for
push; `ssuder.com`, Wikimedia, Unsplash, Pexels and every other image host are
refused at the proxy. You cannot fetch a stock photo or verify the live site
from inside the session. Ask Sean to send images.

## Things that will bite you

- **Measure, do not eyeball.** Most real bugs here were invisible by eye and
  obvious under measurement: hero text at 1.72:1 contrast, a reel clipping a
  descender by 0.9px, a crossfade dipping 4.83 luminance levels, a pan snapping
  0.00685 of scale in two frames. Drive Chromium and check numbers.
- **The reel has invariants.** Its clip window must stay exactly one item tall
  or it stops landing on a word — fix vertical positioning with `line-height`,
  never by changing the height. `data-spin-min` (currently 460) must be re-derived
  whenever the longest label changes: the h1 holds at 40px on small screens and
  the hero gutters take 40px of viewport.
- **Never upscale an image to fit a slot.** Two slides have been soft for this
  reason; one was removed. If the source is smaller than the slot, ship it at
  native size or ask for a bigger original.
- **Check CSS specificity before adding a rule.** `.hero h1` has out-specified
  a bare `.spin-h1` and silently clipped the headline before. Verify computed
  styles in the browser rather than assuming a new rule wins.
- **Inherited colour is not a given.** `.cta` paints navy but carries no `.dark`
  class, which once left a lede at 1.1:1 on eighteen pages.
- **One source, not two.** Repeated copy has drifted twice — a jurisdiction
  count hardcoded in eight places, and two reel word lists. Both now derive from
  one value. Prefer that over keeping duplicates in step.
